毎朝この時刻に、世界のどこかでコンピュータが1台生まれ、31秒だけ働いて、消えます。

そのあいだに何が起きているのかを、順を追って説明します。

31秒のあいだに起きること

日本時間の朝6時。あなたが寝ているあいだに、GitHub という会社のサーバーで次のことが順番に実行されます。

  1. 0秒

    まっさらなコンピュータが用意される

    GitHub が Linux の入った仮想マシンを1台つくります。中身は空っぽです。

  2. 2秒

    プログラム一式が運び込まれる

    あなたが GitHub に置いたファイル（watch フォルダの中身、設定、これまでの記録）が、そのコンピュータにコピーされます。

  3. 5秒

    BIS のサイトに新着を聞きにいく

    国際決済銀行（BIS）が公開している一覧を読み込み、そこからバーゼル委員会に関するものだけを選び出します。

  4. 6秒

    知らない記事があるか照合する

    持ち込んだ記録と見比べて、初めて見る記事を探します。あれば「今日初めて見た」と書き込みます。

  5. 8秒

    ウェブページを組み立てる

    記録をもとに HTML を1枚つくります。新しい日付が上に来るように並べ、3日以内に初めて見た記事に NEW を付けます。

  6. 31秒

    ページを公開し、コンピュータは消滅する

    できた HTML を公開用の場所に送り、更新した記録を GitHub に書き戻して、仮想マシンは破棄されます。

なぜ「消えるコンピュータ」で困らないのか

ここが一番わかりにくいところです。毎回まっさらなコンピュータが使われるということは、前回の作業内容が何も残っていないということです。昨日どの記事を見たのかも、覚えていません。

そこで、記録だけを GitHub 本体に書き戻しています。仕事を終えたコンピュータが、自分のノートを郵送してから消えるようなものです。翌朝の新しいコンピュータは、そのノートを受け取ってから仕事を始めます。

この記録が state/items.json というファイルです。記事ごとに「初めて見た日時」が入っていて、この値は一度書いたら二度と書き換えません。書き換わってしまうと、古い記事に毎朝 NEW が付き直すことになります。

新着はどうやって知るのか

BIS のサイトを人間のように読んでいるわけではありません。多くのサイトは、更新のお知らせ専用のファイルを別に用意しています。RSS と呼ばれるものです。

中身は「見出し・リンク・日付・短い説明」が並んだだけの単純なデータです。デザインも広告も入っていないので、プログラムから読むのが簡単です。BIS の場合、直近10件ぶんが入っています。

ただし、そこには BIS 全体のお知らせが混ざっています。人事の発表も、決済分野の別組織のものも一緒です。そこで「Basel Committee」などの言葉を含むものだけを選び出しています。今のところ、10件中2件がこれに当てはまります。

10件しか入っていないので、もし1か月止まっていると、そのあいだの発表を取りこぼします。毎朝動かしているのはそのためでもあります。

なぜサーバー代がかからないのか

あなたがサイトを開いたとき、実は何も計算されていません。朝6時の時点でできあがった HTML ファイルが1枚置いてあるだけで、それをそのまま送っているだけです。

ニュースサイトの多くは、誰かが開くたびにデータベースを調べてページを組み立てています。だからサーバーが必要で、費用もかかります。こちらは朝に1回だけ組み立てて、あとは置いておく方式です。

この方式を静的サイトと呼びます。速く、壊れにくく、そしてこの規模なら無料で公開できます。

それぞれのファイルの役割

プログラムは仕事の内容ごとに分かれています。あとから直したいとき、どこを見ればよいかがはっきりします。

config/sources.toml
設定ファイル。どのサイトを見るか、何件表示するか、NEW を何時間出すか。あなたが手を入れる場所は基本的にここだけです。金融庁や日銀を追加したくなったら、このファイルに数行足します。
watch/fetch.py
RSS を取ってきて読み解く係。形式が少しずつ違う何種類かの RSS を、同じやり方で扱えるようにしています。
watch/state.py
記録の出し入れをする係。「初めて見た日時」を守る役目もここが持っています。
watch/render.py
HTML と RSS を組み立てる係。並び順、月の区切り、NEW の判定、見た目のすべて。
watch/main.py
進行役。上の3つを順番に呼び出します。
.github/workflows/build-deploy.yml
朝6時の段取り書。GitHub はこのファイルを読んで、何時に何をするかを知ります。

いま眠っている機能

watch/enrich.py というファイルがありますが、今は一度も動いていません。英語の見出しを日本語に訳し、要約をつけ、重要度を点数化する係です。

これを動かすには外部のサービスを呼ぶ必要があり、費用と、鍵を預ける手間がかかります。まず訳がなくても困らないかを確かめてから決めることにしたので、設定で止めてあります。設定を1か所書き換えれば動き出します。

うまく動かなくなったとき

朝になってもページが更新されない

GitHub の Actions タブを開くと、毎朝の実行履歴が並んでいます。赤い印が付いている行をクリックすると、どの段階で止まったかが読めます。

記事が1件も出なくなった

異常とは限りません。バーゼル委員会の発表は月に数件で、何週間も何もない時期があります。ページの一番下に最終更新の時刻が出ているので、そこが今朝の日付なら正常に動いています。

古い記事に NEW が付きっぱなしになる

記録の中の「初めて見た日時」が書き換わっている可能性があります。本来は一度書いたら変わらない値です。
