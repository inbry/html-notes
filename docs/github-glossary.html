GitHub のことば

このサイトを作るあいだに出てきた用語を、出てきた場所ごとに並べました。まず全体の地図から。

Git と GitHub は別物です。ここが最初の混乱どころなので先に。

Git は、あなたのPCに入っている道具です。ファイルの変更を記録して、いつでも過去に戻せるようにします。ネットにつながっていなくても動きます。GitHub は、その記録を預かってくれる会社のサービスです。Git がなくても GitHub は使えますし、その逆も成り立ちます。今回は両方を使いました。

1

あなたのPCで出てきたことば

PowerShell に打ち込んだコマンドまわり。

リポジトリ
ファイル一式と、その変更履歴をまとめて入れておく箱。日本語では「レポジトリ」と書くこともあります。
bcbs-watch フォルダがそれです。git init を実行した瞬間に、このフォルダはリポジトリになりました。
git init
「このフォルダを Git で管理します」という宣言。フォルダの中に .git という隠しフォルダができ、そこに履歴が溜まっていきます。
git add
記録に含めるファイルを選ぶ操作。まだ記録はされません。写真を撮る前に、誰が写るかを決める段階だと思ってください。
-A は「全部」という意味です。
コミット
選んだ状態を1つの記録として確定させること。ここで初めて履歴に残ります。あとから「この時点に戻す」ができるのは、コミットした地点だけです。
-m "Initial commit" の部分は、その記録につける名前です。あとで見返したときに何をしたか分かるように書きます。
ブランチ / main
履歴の枝分かれのこと。複数人で作業するとき、それぞれ別の枝で試して、あとで合流させます。
一人で使う場合は枝は1本だけです。その1本の名前が main です。git branch -M main は、その名前を付ける操作でした。
リモート / origin
手元ではない、ネット上の保管先のこと。origin はその保管先に付けたあだ名で、慣習的にこの名前が使われます。
git remote add origin https://github.com/inbry/bcbs-watch.git は、「これから origin と呼ぶ送り先は、この URL です」という登録でした。
push
手元の記録を、リモートに送る操作。逆に、リモートから手元へ持ってくるのは pull と呼びます。
今回は最初の1回だけ実行しました。以降の更新は GitHub 側で自動的に行われるので、あなたが push することはありません。
.gitignore
記録に含めないファイルを書いておく一覧。書いておくと git add -A をしても無視されます。
毎朝作り直される public フォルダと、要件定義書がここに入っています。
Git Credential Manager
パスワードの代わりに認証を覚えてくれる仕組み。push のときに一度だけブラウザが開いたのがこれです。以降は聞かれません。
2

GitHub の保管庫で出てきたことば

ブラウザで設定した項目。

Public / Private
リポジトリを誰でも見られるようにするか、自分だけにするか。
今回は Public を選びました。無料プランでは Private のままサイトを公開できないためです。だから公開前に、設定ファイルから所属が分かる記述を消しました。
Settings
リポジトリごとの設定画面。歯車のアイコンです。似た名前でアカウント全体の設定もあるので、どちらを開いているかは注意が必要です。
Workflow permissions
自動実行のプログラムに、どこまで許すかの設定。
「Read and write permissions」に変えたのは、毎朝の処理が記録を書き戻す必要があるからです。初期状態は読み取りだけなので、変えないと毎朝失敗します。
GITHUB_TOKEN
自動実行のプログラムが GitHub を操作するための、その場かぎりの合鍵。実行が終わると無効になります。あなたが用意するものではなく、自動で発行されます。
上の「Workflow permissions」は、この合鍵にどこまでの権限を持たせるかの設定でした。
Secrets
パスワードや API キーなど、人に見せられない値を暗号化して預けておく場所。プログラムからは読めますが、画面上では中身が伏せられます。
翻訳を有効にするときに使う予定の場所です。今は何も入れていません。
3

朝だけのコンピュータで出てきたことば

毎朝6時に動く部分。設定ファイル build-deploy.yml の中身です。

GitHub Actions
GitHub が用意している自動実行の仕組み。「こういうときに、こういうことをして」と書いておくと、そのとおりに動きます。無料枠があり、この規模なら費用はかかりません。
ワークフロー
その「何をするか」を書いた手順書。.github/workflows/ というフォルダに置くと、GitHub が自動的に見つけて読み込みます。
拡張子の .yml は YAML という書き方の印です。字下げで階層を表す形式で、字下げがずれると動かなくなります。
ジョブ / ステップ
ワークフローの中の単位。ジョブが大きなまとまりで、その中に細かいステップが並びます。
今回は build（組み立て）と deploy（公開）という2つのジョブがあり、build の中に「ファイルを持ち込む」「Python を用意する」といったステップが並んでいます。
ランナー / ubuntu-latest
実際に処理を行うコンピュータのこと。GitHub が貸してくれます。
ubuntu-latest は「最新の Ubuntu（Linux の一種）を使う」という指定です。毎回まっさらな状態で用意され、終わると破棄されます。
cron
「何時に動かすか」を表す古くからの書き方。5つの数字で分・時・日・月・曜日を指定します。
"0 21 * * *" は「毎日21時00分」。ただし世界標準時なので、日本時間では翌朝6時になります。* は「毎回」の意味です。
workflow_dispatch
手動で動かせるようにする指定。これを書いておくと、Actions タブに「Run workflow」ボタンが出ます。
時刻を待たずに試したいときに使います。あなたが最初に押したボタンがこれです。
concurrency
同じ処理が重ならないようにする指定。前の実行が終わるまで、次を待たせます。
記録を書き戻す作りなので、2つが同時に動くと記録が壊れます。それを防いでいます。
アーティファクト
ジョブが作った成果物を、次のジョブに引き渡すための一時的な置き場。
build が組み立てた HTML をここに置き、deploy がそれを受け取って公開しています。
4

公開まわりのことば

GitHub Pages
リポジトリの中身をそのままウェブサイトとして公開してくれる機能。HTML を置くだけでよく、サーバーの用意も費用も不要です。
Source
Pages が「どこから」ページを取ってくるかの設定。
「Deploy from a branch」ではなく「GitHub Actions」を選んだのは、毎朝の処理が作った HTML を渡す方式にしたからです。
deploy
できたものを実際に公開する操作。「配備する」という意味の英語です。
実行画面で deploy のジョブに URL が表示されていたのは、そこが公開の最終地点だからです。
無料プラン / Pro
GitHub の料金体系。無料でもほとんどのことができますが、いくつか制限があります。
Private のリポジトリからサイトを公開するには Pro が必要でした。そのため今回は Public を選んでいます。

このプロジェクトで実際に出てきた用語だけを収めています。2026年9月時点。
